# 🎙️ VOX Walkie-Talkie (Push-to-Talk)

แอปพลิเคชัน **Push-to-Talk (Walkie-Talkie)** สไตล์วิทยุสื่อสาร สำหรับโทรศัพท์มือถือ (iOS / Android) และคอมพิวเตอร์

เวอร์ชันปัจจุบันเป็น **เว็บ static ล้วน 100%** — ไม่มีเซิร์ฟเวอร์ของตัวเอง ไม่ต้องใช้ Python ไม่ต้องติดตั้งอะไรเลย
รันบน **GitHub Pages** ได้ทันที และใช้งานได้จากทุกเครือข่าย (ไม่ต้องอยู่ Wi-Fi วงเดียวกันแล้ว)

---

## ✨ จุดเด่นและฟีเจอร์หลัก

1. **Static ล้วน รันบน GitHub Pages ได้ 100%**:
   - ไม่มี backend, ไม่มี build step, ไม่มี dependency ที่ต้องติดตั้ง
   - deploy แล้วใช้งานได้จากทุกที่ ทุกเครือข่าย
2. **Mobile-First PWA**: กด "Add to Home Screen" แล้วใช้เป็นแอปเต็มจอได้
3. **ระบบ Push-to-Talk แท้ (Half-Duplex Arbitration)**:
   - กดค้างเพื่อพูด (Hold) หรือแตะสลับ (Toggle)
   - ล็อกช่องสัญญาณขณะมีคนพูด ป้องกันเสียงชนกัน + เสียงแจ้งเตือนเมื่อช่องไม่ว่าง
   - ตัดสัญญาณอัตโนมัติเมื่อกดค้างเกิน 60 วินาที
4. **คุณภาพเสียง Real-time (WebRTC + Opus 48kHz)**: latency ต่ำ ~20-50ms, มี noise suppression และ echo cancellation
5. **ระบบเสียงวิทยุสังเคราะห์ (Web Audio API)**: Motorola chirp, Roger Beep, Channel Busy Tone, haptic vibration
6. **ป้องกันหน้าจอดับ (Screen Wake Lock API)**
7. **หลายช่องสัญญาณ**: CH-1 ALPHA, CH-2 BRAVO, CH-3 CHARLIE, CH-4 DELTA
8. **🔒 ห้องส่วนตัว (มีรหัสผ่าน)**: แยกจากช่องสาธารณะทั้ง topic และข้อความ (เข้ารหัส AES-256-GCM ด้วยรหัสผ่าน) — ดูหัวข้อถัดไป
9. **QR Code** สำหรับเปิดบนมือถือ (ใช้ได้ทุกเครือข่าย ไม่ต้องอยู่วง Wi-Fi เดียวกัน)

## 🏗️ สถาปัตยกรรม (สิ่งที่เปลี่ยนไปจากเดิม)

เดิมโปรเจกต์นี้ใช้ `server.py` (aiohttp + WebSocket) เป็นทั้งเซิร์ฟเวอร์ไฟล์และ signaling ซึ่ง **รันบน GitHub Pages ไม่ได้**
เพราะ GitHub Pages เสิร์ฟเฉพาะ static files เท่านั้น จึงย้ายทุกอย่างขึ้นฝั่ง client:

| ส่วน | เดิม (Python) | ตอนนี้ (static) |
|---|---|---|
| เสิร์ฟไฟล์ | `server.py` (aiohttp) | GitHub Pages |
| HTTPS / ใบรับรอง | self-signed cert (`cert.pem`/`key.pem`) | HTTPS ของ GitHub ตามมาตราฐาน (ไม่ต้องกดข้าม warning) |
| Signaling (SDP/ICE) | WebSocket `/ws` บนเซิร์ฟเวอร์ | **MQTT over WSS** ผ่าน broker สาธารณะ |
| รายชื่อสมาชิกในช่อง | `channels[...]['users']` ในหน่วยความจำ | retained message + heartbeat บน topic `presence/#` |
| ล็อก PTT (ใครมีสิทธิ์พูด) | `channels[...]['locked_by']` | retained message บน topic `state` |
| 60 วินาที safety cutoff | `loop.call_later(60)` บนเซิร์ฟเวอร์ | timer บน client ของผู้พูด |
| เสียง | WebRTC mesh ผ่านเซิร์ฟเวอร์เดิม | WebRTC mesh เหมือนเดิม (ไม่ผ่าน broker) |

**หลักการสำคัญ**: เสียงวิทยุยังเดินทางแบบ P2P ผ่าน WebRTC 一如เดิม — MQTT ทำหน้าที่เฉพาะ
"ส่งสัญญาณและรู้ว่าใครอยู่ในช่อง" เท่านั้น และเนื่องจากไม่มีเซิร์ฟเวอร์กลาง จึงใช้
**retained message** เป็นตัวเก็บสถานะร่วมกัน: ใคร publish คนสุดท้ายถือว่าล็อกช่องไว้
(เมื่อกดพร้อมกันพอดี จะมีฝั่งเดียวที่ได้ล็อก อีกฝั่งจะได้รับคำตอบ `ptt_denied` แล้วเล่นเสียง busy)

Broker สาธารณะที่ใช้ (เรียงลำดับที่จะลอง ไม่ต้องสมัครสมาชิก ไม่ต้องมี API key):

1. `wss://broker.emqx.io:8084/mqtt`
2. `wss://test.mosquitto.org:8081/mqtt`
3. `wss://broker.hivemq.com:8884/mqtt`

ถ้า broker แรกล่ม client จะสลับไป broker ถัดไปเอง (ทุกเครื่องลองลำดับเดียวกันเพื่อให้มาบรรจบกัน)

## 🔒 ห้องส่วนตัว (Private Room with Password)

กดปุ่มช่องสัญญาณด้านบน แล้วกรอก **ชื่อห้อง + รหัสผ่าน** ในส่วน “ห้องส่วนตัว” กดเข้าห้องได้ทันที

- **ทุกคนต้องใช้ชื่อห้องและรหัสผ่านเดียวกัน** จึงจะเห็นกัน (เหมือนกุญแจห้อง)
- ออกจากห้องได้โดยการกดเลือกช่องสาธารณะ (CH-1..CH-4) ตามปกติ
- ระบบจะจำชื่อห้องและรหัสผ่านไว้ในเครื่องนั้น เพื่อเข้าห้องเดิมอัตโนมัติตอนเปิดแอปใหม่

### มันปลอดภัยแค่ไหน (เข้าใจตรงกัน)

เนื่องจากไม่มีเซิร์ฟเวอร์ ระบบจึงป้องกัน 2 ชั้น:

| ชั้น | วิธี | ได้อะไร |
|---|---|---|
| 1. ชื่อ topic | `sha256(ชื่อห้อง \| รหัสผ่าน)` → `vox-ptt/v1/r/<hash>/...` | คนที่รู้แค่ชื่อห้องเดาช่องไม่ได้ |
| 2. เข้ารหัสข้อความ | PBKDF2 (200k รอบ) → **AES-256-GCM** ทุกฉบับ รวมถึง retained state/presence | คนที่แอบ subscribe `r/#` จะเห็นแต่ binary ไม่ใช่ข้อความ |

สิ่งที่**ไม่ได้**ป้องกัน:

1. ไม่มีการยืนยันตัวตน — “นามเรียกขาน” เป็นเพียง label ใครก็ตั้งได้
2. รหัสผ่านเก็บใน `localStorage` ของเครื่องนั้น (สะดวกตอนเปิดใหม่ แต่เครื่องร่วมกันใช้ควรมีรหัสผ่านที่เดายาก)
3. คนที่มีรหัสผ่านทุกคนเท่าเทียมกัน ไม่มีระบบแอดมิน/เตะสมาชิก
4. ถอดรหัสย้อนหลังนอกเครื่องทำได้ถ้ารหัสผ่านสั้นมาก (ค่า PBKDF2 ทำให้แพงขึ้น แต่ไม่ใช่กำแพง)
5. ข้อความที่ดักฟังได้ (ciphertext) นำกลับมาเล่นซ้ำได้ — สถานะทุกอย่างมี timestamp แล้วจะถูกคัดออกเมื่อเก่า

## 🚀 Deploy ขึ้น GitHub Pages (ฟรี 100%)

**ค่าใช้จ่าย: 0 บาท** — GitHub Pages ใช้ฟรีกับ **public repository** บน GitHub Free,
ไม่มี build step ไม่มีค่า hosting และฝั่งแอปก็ไม่มี service ที่เสียเงิน
(broker MQTT สาธารณะใช้ฟรี, STUN ของ Google ฟรี, WebRTC เป็น P2P)

> ข้อจำกัดของ GitHub Free: Pages ใช้ได้กับ **repo สาธารณะ** เท่านั้น (private ต้องมีแผน Pro ขึ้นไป)
> ขีดจำกัด: repo ≤ 1GB, เว็บไซต์ ≤ 1GB, bandwidth แบบ soft limit ~100GB/เดือน (แอปนี้ไม่ถึง 1MB ต่อโหลด)

### ขั้นตอน (ทำครั้งเดียว)

```bash
git init
git add .
git commit -m "VOX Walkie-Talkie - static PTT app"
git branch -M main
git remote add origin https://github.com/<username>/<repo-name>.git
git push -u origin main
```

จากนั้นบน GitHub:

1. เข้า **Settings → Pages**
2. ที่ **Source** เลือก **GitHub Actions** (มี workflow พร้อมแล้วที่ `.github/workflows/deploy-pages.yml`)
   - หรือเลือก **Deploy from a branch** → branch `main` → folder **`/ (root)`** ก็ได้ (ไม่ต้องใช้ workflow)
3. รอ Actions รันเสร็จ (~20 วินาที) แล้วเปิด `https://<username>.github.io/<repo-name>/`
4. ทุกครั้งที่ push ครั้งต่อไป เว็บอัปเดตอัตโนมัติ

ไม่มีขั้นตอน build ใดๆ เพราะเป็น static ล้วน ทุก path ในโปรเจกต์เป็นแบบ **relative**
จึงใช้ได้ทั้ง `username.github.io` (root) และ `username.github.io/repo/` (subpath) — ทดสอบแล้ว

> ข้อควรระวัง: อย่า commit โฟลเดอร์ `legacy/` ขึ้น GitHub (มี `key.pem`) — กันไว้ทั้งใน `.gitignore`
> และใน workflow (`rm -rf legacy`) เรียบร้อยแล้ว

## ⚠️ ข้อจำกัดที่ควรรู้

1. **Broker สาธารณะ** — ใช้ฟรี ไม่มี SLA และเป็นแบบ open:
   ทุกคนที่ทราบ topic (`vox-ptt/v1/ch/<ช่อง>`) สามารถอ่าน/เขียนข้อความได้
   จึงเหมาะกับการใช้งานส่วนตัว/ทดลอง ไม่เหมาะกับระบบงานสำคัญ
2. **ไม่มี TURN server** — ถ้าอยู่หลัง NAT ที่เข้มงวดมาก (บางเครือข่ายมือถือ)
   อาจต่อ WebRTC ตรงกันไม่ได้ ต้องเพิ่ม TURN เอง (ค่าใช้จ่าย)
3. **ไม่มีระบบสมาชิก/ยืนยันตัวตน** — "นามเรียกขาน" เป็นเพียง label ที่ใครก็ตั้งได้
4. **Mesh ทุกคนต่อถึงกัน** — จำนวนผู้ใช้ในช่องเดียวควรจำกัด (~10-15 คน) เพื่อประสิทธิภาพ
5. **Presence จะค้าง ~45 วินาที** ถ้าผู้ใช้ปิดเบราว์เซอร์แบบกะทันหัน (ปิดหน้าปกติจะเคลียร์ทันที)
6. **หลายแท็บบนเบราว์เซอร์เดียวกัน** ใช้ `userId` อันเดียวกัน (เก็บใน localStorage)
